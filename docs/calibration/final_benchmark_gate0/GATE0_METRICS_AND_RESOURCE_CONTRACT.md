## 1. Query accounting

For category `c`, let `T_c` be its exact official TEST **image-event** count in the approved manifest. Candidate category budgets are:

```text
Real-IAD: cap_c = floor(0.03 * T_c)
VisA:     cap_c = floor(0.10 * T_c)
```

This hard cap is new protocol, not implied by historical E6/D2 soft selection. For policy/arm `m`, category `c`, paired condition `p`, and image event `t`, let `a_{m,c,p,t}=1` only when a query is genuinely executed and paid; otherwise it is 0. Define `Q_{m,c,p}=sum_{t=1}^{T_c} a_{m,c,p,t}` and realized rate `r_{m,c,p}=Q_{m,c,p}/T_c`, with maximum allowance `B_c=floor(rho*T_c)`. Equal maximum query budgets do not imply identical realized query counts or rates.

Interpret and report the comparisons in three ways. **Equal-cap comparison:** the policies have the same maximum label allowance, and their complete-system BER comparison remains valid as an equal-maximum-budget deployment comparison even if realized spending differs. **Approximately equal-realized-budget comparison:** for each condition define the category-equal dataset macro `r_macro,m,p=(1/C) sum_c r_{m,c,p}`. Only add this description when the approved absolute rate difference `|r_{A,c,p}-r_{B,c,p}|<=0.003` passes for every category within each paired condition and the category-equal dataset macro difference `|r_macro,A,p-r_macro,B,p|<=0.003` passes within each condition; a matching macro cannot substitute for any category-level pass. The tolerance remains a researcher-review candidate. **Performance versus expenditure:** when counts/rates differ beyond tolerance, report BER alongside actual labels purchased and do not attribute a BER gain uniquely to better query selection when the winning method purchased more labels.

For every image proposal, record four fields independently: `proposed`, `executed`, `Source Group suppressed`, and `hard-cap suppressed`. If the group already has an executed query, group suppression is recorded first. Otherwise, a proposal executes only if the category count is below its cap; if at cap, record hard-cap suppression. Increment the query counter only for an executed query. The first eligible executed proposal in a group reserves its one query. N-shadow inherits F-B's exact receipt and has no query count of its own. A selected label is disclosed only after the entire group has been scored and sealed.

The proposed BEA action history is event-level. After a Real-IAD group has sealed, replay final action flags in registered view order: one `1` at most for the executed query; all other events are `0`, including no-proposal and suppressed proposals. Apply the historical price recurrence after each flag, but keep the pre-group price for all proposals in that group; the new price applies to the next group. Margin utility history likewise receives every pre-group utility after the whole group is sealed, regardless of query proposal, execution or suppression. These are candidate rules requiring researcher approval.

Realized counts need not equal nominal targets: floor rounding, one-query-per-group, the policy and the hard cap may lower them. `T_c` counts image events, not groups or eligible queries. For each policy/category/condition report `Q_{m,c,p}`, `r_{m,c,p}`, `B_c`, and unspent budget `B_c-Q_{m,c,p}`. Report cap status as the first image-event/group where the cap became exhausted, or explicit `NOT_EXHAUSTED`; include hard-cap-suppressed and Source-Group-suppressed proposal counts, and normal/defect labels obtained. For each registered pairwise contrast and condition report query-count and rate differences, the category-equal dataset macro rate difference, and whether the approved rate-matching criterion passes at both levels. The 0.003 criterion is a candidate pending review. Exhaustion never triggers a policy change, forced query, top-up, or arm-specific budget compensation. For VisA's approximately 150–201 TEST events/category, one additional query changes the rate by about 0.005–0.0067, so it will typically fail the proposed 0.003 category tolerance. Do not relax the tolerance after seeing results.

## 5. Memory and resource accounting plan

Use byte-level component accounting and distinguish physical shared read-only buffers from per-arm logical state:

- **Encoded TEST feature:** E6 expects one FP32 `(784,4096)` map, 12.25 MiB for one current image. Do not retain a full TEST dense feature cache. Encode in stream order and release per-category temporaries at a declared boundary.
- **C64 feature cache:** if the full `(64,784,4096)` FP32 tensor is cached, it is `822,083,584` bytes = 784 MiB per category, shared read-only among arms; 42 categories resident would be about 32.2 GiB. This is a shape-based upper estimate, not a measured allocation. Keep it per-category/CPU-backed or prove a different bounded cache plan before Gate 2. Each arm's current-state C64 scores and threshold evidence remain separate.
- **Fixed bank:** current R7/B record gives 8,192×4,096 FP16 = 67,108,864 bytes (64 MiB) per physical bank. Record logical per-arm references and actual physical sharing; do not call equal fixed-bank bytes equal total method storage.
- **Greedy and C1:** count every tensor by shape, dtype, device, plus source group, identity, position, signs, indexes, allocator reserve, and staging copies. Greedy is K=1024 per native layer; C1 is K=1024. Capture actual before/after bytes rather than relying on a nominal K alone.
- **Signed kNN:** account for R10's FP32 feature FIFO at K=1024 (16 MiB of feature values alone), plus sign, position, 32-byte source digest per slot, indexes, and temporary distances.
- **Other buffers:** current image, each arm's native maps/top-k patches, C64 scores, query receipts, private/public logs, checkpoint/serialization buffers, framework/model allocations, and allocator high-water marks. Distinguish persistent memory from peak temporary memory.

Do not materialize all dataset features or hold every category's C64 patch tensor on GPU. Process a category under a measured limit and release category-specific state/caches before the next one, with persisted checksums and recovery semantics frozen later.
