# FS4 R1 resource assessment

The E cache retains FP32 features without silent conversion or eviction: each normal uses 12,845,056 tensor bytes and the 1,024-group limit is 13,153,337,344 bytes (12.25 GiB), excluding Python objects, native memory, checkpoints and process overhead. Capacity overflow raises. `fs4_resources.preflight` checks free host RAM and disk against caller-declared budgets; `run_with_timeout` provides a spawned-process wall-time limit. The timeout gate was exercised with a synthetic sleeping child. An immutable checkpoint stores the retained tensors plus metadata, so repeated full checkpoints can consume approximately 12.25 GiB apiece before overhead.

At the initial resource observation, host RAM was 68,523,839,488 bytes total and 48,911,159,296 bytes available; the E: filesystem had 287,929,991,168 bytes free. CUDA reported 25,756,696,576 bytes total and 24,445,452,288 bytes free. These are point-in-time observations, not reserved capacity.

The final synthetic CUDA test used an 8,192 × 4,096 FP16 static bank, 24 Greedy slots, one C1 anchor, and 12 cached full FP32 features. For batches of 1, 4 and 12 exact source-excluded rescores, elapsed times were respectively 0.144, 0.660 and 2.165 seconds. Across 17 calls, mean was 0.17468 seconds, median 0.17651 seconds and p95 0.19075 seconds. Process RSS was 2,424,795,136 bytes, GPU peak allocated memory 484,641,280 bytes, and the 12 cache tensors used 154,140,672 bytes. Native direct dense scoring against the synthetic 8,192-prototype bank took 0.01108 seconds and peaked at 399,885,312 allocated GPU bytes in its separate probe.

Linear extrapolation of the observed rescore mean gives about 178.87 seconds for one 1,024-image refresh, or about 4.97 hours for 100 such refreshes. This is a rough lower-information estimate: the benchmark's Greedy and C1 banks are small, it does not measure a 1,024-image cache, and timing may change with memory occupancy, concurrent work and checkpoint I/O. No approximation or evidence reduction was used. Review the actual workload and timeout budget before authorizing a campaign; these observations do not establish that it fits available resources.
