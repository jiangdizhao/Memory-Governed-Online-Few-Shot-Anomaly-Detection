# Native scorer and writer fidelity

The production path calls the unchanged `p0_protocol_audit.build_vmb` for the exact four caller-supplied Support augmentation sets, R1 `_native_dense_score` for the full fused map and Top-32, the native V0.2 `MemoryArm.update` and `greedy_slot`, the native `PatchVMB.update_corrections_from_topk`, and R1 `_record_c1_source_group_updates`, `_filtered_c1_codebook`/`_c1_score_delta`, `corrected_dense_map` and `max_score`. `native_bridge` supplies dynamic codebook snapshots. The frozen R3 C1-Full configuration is checked before a fresh native K=1024 C1 allocation; correction weight is 1.0. The historical implementations and configurations remain unchanged.

The new dependency call graph uses P0's support builder, R1 dense/C1 helpers and digests, R2's temporary C1 switch helpers, R3's correction-config validator, `native._fixed_bank_digest`, native bridge snapshots, and V0.2 writer/slot code. Those executed functions do not load historical additional-normal reference scores or features. Historical modules also contain unrelated archived orchestration and reference-reading functions; those functions are not invoked. The FS4 runtime contains no C64 identifier and accepts only four Support augmentation keys and legally disclosed online feedback. The test comparing BEA equations constructs an artificial 64-number vector solely as a mathematical reference for the old pure function; the new operational function never calls that old C64-accepting function.

Synthetic CPU tests exercised direct native versus untouched-shadow scoring, exact V0.2 writer versus shadow update, real native append/replacement and source unions, C1 updates for both feedback labels, C1 group filtering, dense Top-32 reselection and read-only live-state checks. A separate native CPU five-view smoke ran the integrated feedback path. Its fixed bank is a small manually constructed synthetic reference, and the four-Support builder dispatch test uses a native-compatible synthetic builder double. Thus these checks do not establish full 8,192-prototype build parity, real DINO feature parity, CUDA numerical parity, or performance on any dataset. No DINO weights or scientific images were loaded.

The new BEA is a named variant, not exact historical D2: it replaces the old additional-normal score scale with the lagged unlabeled MAD, introduces one random group slot and exploration, and uses the requested 0.037 price target. Its novelty geometry follows the E6 four-Support/queried-normal CLS implementation; a synthetic parity test compares that implementation directly. The shared query reference and writer reference are frozen Support-derived states, whereas historical calibration-coupled paths used additional-normal references.
