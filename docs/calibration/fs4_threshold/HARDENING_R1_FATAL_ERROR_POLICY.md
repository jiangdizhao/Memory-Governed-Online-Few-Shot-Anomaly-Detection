# Fatal and recoverable error policy

`fs4_errors.py` defines `FS4InsufficientEvidence` and `FS4RecoverableAvailabilityError` separately from `FS4FatalIntegrityError` and its provenance, native-scoring and live-state-mutation subclasses. Fewer than 12 groups, low ESS and duplicate successfully applied tokens hold the threshold. An explicitly signaled temporary availability failure can be retried with the same scorer/evidence version. Attempted and successful tokens are recorded separately.

Malformed evidence, missing or mismatched cached features, Greedy source or active-prototype mismatch, C1 source mismatch, live-state mutation, native exceptions and nonfinite rescored values are fatal. Unexpected exceptions are wrapped and re-raised as fatal native-scoring failures; they are not converted into an ordinary held threshold. Greedy writer/mirror divergence invalidates provenance. The trajectory is latched failed on an event exception, preventing it from advancing to a later event.

E computes all requested G/GC rescores before applying either update, stages changes in a copy of the shared estimator, and publishes both changes together. A fatal mid-rescore does not advance successful tokens or thresholds. CPU fault injection covers retry, nonfinite output, missing cached evidence, C1 provenance and a native scorer that mutates the live Greedy bank before throwing. A native CPU recovery test injects a failure during the sixth of twelve actual E rescores and compares the replayed event, query, feedback and final state against the uninterrupted reference.
