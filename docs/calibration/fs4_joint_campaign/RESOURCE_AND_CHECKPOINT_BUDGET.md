# Resource and checkpoint budget

`fs4_joint_campaign_resources.py` computes the frozen storage schedule before Stage A. It counts 45,885 event encodings across S/CL/CE, 15,295 base G/GC scoring pairs per trajectory, 12 four-Support self-score sets, and up to 1,171,243 exact E rescoring invocations per E-bearing trajectory (S and CE), or 2,342,486 campaign-wide under the conservative one-normal-query-per-group upper bound.

Each cached full feature is 784 × 4,096 FP32 = 12,845,056 bytes. Capacity 1,024 is 13,153,337,344 bytes (about 12.25 GiB); category maxima are computed from the registered Source Group counts. No precision reduction or cache eviction is permitted.

Every 1,000 completed global events and each category start/end is an immutable checkpoint. The current dimensionally explicit upper bound sums the E cache at every scheduled checkpoint plus a frozen 256 MiB per-snapshot allowance for native/controller/checkpoint structures. Across 69 snapshots this is 222,964,482,048 bytes of feature caches plus 18,522,046,464 bytes of non-cache allowance, or 241,486,528,512 bytes before reserve (about 224.9 GiB). With 25% reserve this is 301,858,160,640 bytes (about 281.1 GiB), then blinded resources and a separate 2 GiB ledger/output reserve. The 256 MiB allowance is a modeled ceiling, not an observed size; the synthetic benchmark receipt must demonstrate that its maximum non-cache checkpoint payload fits within it. This is an upper bound, not an observed output size. New data remains in a fresh campaign namespace.

Before Stage A the resource gate requires all blinded image resources, enough free disk for that estimate and reserve, at least 32 GiB available host RAM, an NVIDIA GeForce RTX 3090 Ti with at least 24 GiB total memory, and a campaign-bound synthetic benchmark receipt reporting full-dimension rescore and encoder p95 times plus host/GPU peaks. Each arm has a seven-day wall limit and the whole campaign a 21-day limit. These limits do not justify changing checkpoint frequency or any scientific setting.

The prior ~0.175 second rescore observation used relatively small dynamic memories and is not accepted as a full-campaign prediction. A preflight without a valid synthetic benchmark, storage or hardware evidence returns `BLOCKED_RESOURCE_PREFLIGHT`. The current freeze task does not perform real-data staging, actual native Support reconstruction or a full campaign run; resource feasibility on the eventual host remains an activation gate. Resource overrun stops the run and leaves it incomplete.
