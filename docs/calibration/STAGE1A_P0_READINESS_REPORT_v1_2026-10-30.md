# Stage 1-A P0 execution-readiness audit

**Decision:** `P0_PREPARATION_PARTIAL; EXECUTION_BLOCKED`

**Scope:** read-only readiness review and a candidate protocol addendum. No Stage 1-A scientific evaluation was executed. This report does not authorize Stage 1-A, Stage 1-B, Stage 2, or confirmation access.

**Repository reference:** branch `calibration-stage0-contract-20261029`, base `9da175ad3695cbd3d0e0583e2e8d3703c1fb6e2a`. The tracked tree was clean at audit start. Pre-existing untracked experiment and audit outputs remain outside this change; none are staged here.

## Decision summary

The historical Stage 0.75-A package supplies a strong reusable shared trajectory for a focused controller comparison. The 20 class-by-support-seed trajectories, Q-A-TS tape positions, score arrays, memory chains, C64 transport, and historical B3 replay links passed the recorded read-only parity checks. The independent G2 certificate reports package-integrity `PASS`, but the original G2 gate remains `BLOCKED` and the certificate requires researcher review.

The artifacts are insufficient for a full B4/B7/Stage075BOffset replay. They contain only six queried-anchor memory snapshots per trajectory, not anchor scores at every current memory state. The event runner discarded event feature tensors after scoring; no reusable full query-anchor feature cache was identified. Full-event current-memory anchor scoring would require native feature/scorer work under a later authorized run. The historical output also lacks a separate query-label response digest, so its old feedback labels cannot be independently reconciled from the public trace alone. No new labels were requested or read for this audit.

The approved v3 design remains under its separate execution hold. This focused method set changes the comparison registry (including Stage075BOffset and the proposed B6 scope), so this addendum is only a candidate. A separate explicit `STAGE1_EXECUTION_GO`, approval of the focused protocol, and closure/review of the identified preflight blockers are required before any run.

## C. Controller-input reuse and blockers

The machine-readable inventory is in `stage1a_reuse_and_compute_plan_v1_2026-10-30.json`; method requirements are in `stage1a_method_matrix_v1_2026-10-30.json`.

- **Reusable:** all event static/dynamic scalar scores, query positions, event order, pre-event memory versions/digests, writer transitions, per-event B3 replay, and the recorded C64 transport scores/digests. These let threshold-only methods consume one common score/memory path without any controller-dependent query, write, or score trajectory.
- **CPU-reconstructable from reusable values:** B0 and B3; B5a and B5b source-state recurrences; their separately named Frozen-Theta fallback rows. B2 can reconstruct its C64 source-native NumPy quantile initialization, but its causal feedback trajectory also needs queried labels. B1 also needs queried verified-normal labels. No controller is actually evaluated by this readiness audit.
- **Needs native score calls for a complete current-state replay:** B4, B7, and Stage075BOffset need current-memory scores for queried anchors. Queried normals require all-layer leave-source-out scoring. C64 scores already present in the exact memory chain are reusable; query-anchor scores are available only at the six fixed snapshot states. Existing source code stores query features in a private in-memory ledger during execution, but the Stage 0.75-A runner discards event features after event scoring and the saved checkpoints contain only six snapshot memory states plus final writer state—not all intermediate memory states or a portable feature cache.
- **Unavailable historical input for exact reproduction:** a separately verifiable query-label response record/digest is absent. The query-anchor measurement file under the previous audit output is label-bearing and was not decompressed, parsed, or copied. Private checkpoints were not deserialized; only their names/sizes and prior recorded container-member review were used. No labels, masks, confirmation outcomes, or hidden class distributions were read.

`AnchorLedger` enforces one queried anchor per official sample group, rejects overlap with deployed support and C64, and refreshes every eligible anchor after a memory version change. Queried normals are rescored with their source group excluded from every Greedy layer. Queried defects are not written and use the unchanged memory bank. This logic is implemented, but its event-by-event query-anchor score trajectory is absent from the reviewed Stage 0.75-A output.

## C1. Method and startup review

The registered implementation details and current readiness for each requested row are recorded in `stage1a_method_matrix_v1_2026-10-30.json`. Key audit observations:

- The prequential engine predicts before disclosing a queried label; controller feedback and score updates occur after prediction, then the independent shared writer runs, evidence is refreshed for a query or memory-content change, and controllers finalize for the next event. Query selection and memory writes do not depend on thresholds.
- B2 wraps the historical v22 `GuardedDualAnchorThresholdController`: it initializes from the 64 additional C64 scores using the source's NumPy quantile convention (not the D2 `theta0` convention), disables its source normal-only fallback because unqueried labels are unavailable, keeps balanced/fast rescue disabled as in the registered defaults, and ignores unlabeled scores. This is an explicitly adapted sidecar; full-loop historical parity is not claimed.
- B4 is an adapted Dual-ACI sidecar. It updates class-side state only on matching queried labels, and consumes current-version anchor bounds. Its original ACI guarantee does not transfer to sparse selective feedback with dependent, memory-rescored scores.
- B5a and B5b use the shared score stream only. SPOT needs 1,000 initial observations; dSPOT needs 50 local-window observations plus 1,000 residual initialization observations. Their native startup predictions remain missing, alarms do not update the source state, and their separate Frozen-Theta fallback rows must report source/fallback decision fractions. They cannot receive ordinary full-stream BA while source-native predictions are missing.
- From the class lengths, native source coverage is 2,815/3,815 (73.79%), 2,855/3,855 (74.06%), 2,820/3,820 (73.82%), and 2,805/3,805 (73.72%) for SPOT. dSPOT covers 2,765/3,815 (72.48%), 2,805/3,855 (72.76%), 2,770/3,820 (72.51%), and 2,755/3,805 (72.40%). Across these four streams, that is 73.85% SPOT and 72.54% dSPOT. The corresponding startup-unavailable counts are 1,000 and 1,050 events per class. The Frozen-Theta variants can issue a binary decision throughout, but are deployment hybrids, not source-native methods.
- B7 has minimums of 16 queried-normal anchors and 8 queried-defect anchors, descriptive CP delta 0.05, support FPR/FNR limits 0.20, and a 0.01 movement cap. Eight queried defects can activate two-sided processing; they do not imply the stated FNR endpoint can be met. With zero errors, 14 defects are required for the one-sided upper endpoint to be at most 0.20. Errors can require more. The bound is descriptive only and is not certified online population risk under adaptive selection, serial dependence, repeated rescoring, or memory-dependent scores.
- Stage075BOffset is the synthetic `B3+Offset` mechanism, a raw midpoint of the queried-normal and queried-defect medians with a 0.01 movement limit. Its Stage 0.75-B results are synthetic and do not establish real-data benefit. It is a distinct proposed adaptation, not an approved v3 method, not B8-Full, and not an externally established guarantee.
- B6 Sun-CS uses score-quantile events, not the Real-IAD physical-defect target. Its approved source-native/applicability distinctions and endpoint pathology remain. A full-stream comparison is computationally costly under the registered optimized A3 path. This addendum proposes applicability-only reporting and omission of a new full-stream B6 run; that scope change requires researcher approval. B6 should remain in the registry and its previous synthetic/analytical evidence should not be presented as physical-defect classification performance.
- B8 remains a historical synthetic negative control only. No B8 variant is proposed for Stage 1-A. The Stage 0.75-B report found B8-Full matched B3 under its synthetic suite and did not support added mechanism complexity; this does not license tuning or performance claims on the four Real-IAD classes.

## D. Compute and storage evidence

Observed measurements are kept separate from unknown future cost:

- The four class score tracks contain 76,475 shared dynamic values and 76,475 static values total across 20 class × seed trajectories. These values can be replayed through all score-only and threshold-only rows; no per-controller event image scoring is needed.
- Across all 20 trajectories there are 459 tape positions per five seed contexts (2,295 query feedback events). There are 459 unique queried positions across the four class tapes. The snapshot audit covered 386 of those unique positions before the final saved snapshot at `t=3200`; 73 later positions fall at or after that boundary.
- A metadata-only upper-bound count for full current-memory query-anchor scoring is 75,406 anchor-score evaluations across the 20 trajectories if every queried event were an eligible anchor and every later memory-content revision required a rescore. This is an upper bound, not observed workload; actual counts depend on queried labels, source-group eligibility, and B4/B7 anchor retention rules.
- Existing C64 transport provides 76,160 post-write C64 scores across the 1,190 memory updates. Those are reusable for the exact saved trajectories; no extra C64 score call is required if identities and hashes still match.
- The previous six-snapshot native query-anchor audit reports 15,445 score calls, 811.418 seconds elapsed, and peak CUDA allocation 2,433,839,616 bytes. It newly encoded 386 queried images and measured 120 snapshot states. These are historical measurements for that snapshot audit, not a runtime estimate for dense event replay.
- The Stage 0.75-A trajectory files occupy 8,536,638 bytes. Its 12 private checkpoint files occupy 567,274,759 bytes and must remain private. The prior query-anchor measurement payload is 595,552 compressed bytes and contains labels; it is excluded from this commit and was not read. Exact Stage 1-A storage and full-event runtime, CPU RAM peak, CUDA peak, and number of retained query-anchor features are `UNKNOWN`. Do not extrapolate the snapshot runtime linearly.
- Dense replay plan: first freeze exact source/config identities; use the saved score/memory/C64 arrays for all controllers; obtain an explicitly authorized private query-label stream; encode each unique queried image once if a valid local feature cache cannot be proven; then score eligible query anchors at each required current memory using source-group LSO for normals. Share the resulting version-addressed evidence across B4/B7/Stage075BOffset, without allowing any method to affect the tape or writer. Keep all features, labels, and checkpoints private. Emit per-method state/evidence revisions and source/fallback denominators in an immutable manifest.

## E. Proposed focused protocol and remaining approvals

The companion addendum proposes a focused matrix on the four development classes, five support seeds, 3% Q-A-TS seed 37, four deployed supports plus the additional C64=64 normals, frozen native scorer, K=256 shared Greedy bank, and the fixed common horizon `t=1050`. It preserves full-stream operational reporting, class-specific coverage, selective metrics, defined non-overlapping 256-image windows, threshold movement, HOLD/conflict/evidence revision counts, query and memory counts, and shared-score AUROC/AUPRC invariance for threshold-only controllers.

The addendum keeps source-native B5 rows and separate Frozen-Theta fallback rows; it proposes B6 applicability-only and B8 historical-negative-control-only reporting. It adds Stage075BOffset as a distinct candidate row. These are proposed scope/method changes and are not automatically approved by the Stage 0 decision or approved v3 design.

Before execution, researchers must explicitly approve: (1) a separate `STAGE1_EXECUTION_GO`; (2) the focused comparison registry and B6 applicability-only scope; (3) inclusion and naming of Stage075BOffset; (4) resolution or explicit acceptance of original G2's source-execution provenance limitation; (5) a private, causal label-response linkage for any queried-feedback methods; and (6) a full event current-memory anchor scoring/cache plan with measured resource budget. Five-seed source/support/C64 preflight must also be run in the calibration namespace without opening hidden outcomes.
